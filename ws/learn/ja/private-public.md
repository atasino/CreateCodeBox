# 学びカード: 非公開と公開

## 一言で
非公開は、誰が見られるかを、あなたが決められる状態です。公開は、インターネット上の誰もが見られる状態です。

## たとえるなら
自宅の書斎と、駅前の掲示板です。書斎は、あなたが鍵を持ち、誰を入れるかを決めます。掲示板に貼ったものは、通りかかった人みんなが読めます。そして、貼ったあとで、読んだ人に忘れてもらうことはできません。

## いま起きること
- 非公開にするか公開にするかは、GitHub のサイトで選びます。最初は非公開にしてください。
- まず `bash ws/bin/ws.sh publish-check` を実行します。セーブの記録（履歴）の全体に、決まった形式の鍵がないかを調べます。README とライセンスがあるか、セーブしていない変更がないかも調べます。セーブに記録されたメールアドレスが非公開用かも調べます。
- 本名、住所、お客さんのデータのような個人の情報や、ファイルの中に書いたメールアドレスは、この点検では見つけられません。これは、あなたが自分で確かめてください。
- 点検を通ったら、公開するかどうかを、あなたが決めます。公開すると決めたら、会話に、次のどちらかをそのまま打ちます。`publish` か「公開します」です。`pm`（あなたが話しかけるアシスタント）には、あなたの代わりにこのどちらも打たないよう指示してあります。
- そのあと `bash ws/bin/ws.sh publish` が、あなたが登録した repo に作ったものを送ります。送ったあとに、あなたが GitHub のサイトで repo を公開にします。やり方は GitHub の公式の案内にあります。

## 気をつけること
- 公開すると、ファイルだけでなく、消したものを含む履歴の全体が見えます。
- 一度公開すると、取り戻しにくいです。ほかの人がコピーするかもしれません。
- 鍵を一度でも保存したことがあるなら、新しい鍵を作り、古い鍵は使えなくしてください。ファイルを消すだけでは足りません。
- GitHub のサイトでファイルを直したり、プルリクエスト（変更の提案）を取り込んだりすると、GitHub が、あなたのアカウントのメールアドレスを、そのときのセーブに残すことがあります。今後、メールアドレスが残らないようにするには、GitHub の設定「Keep my email addresses private」（Settings → Emails）をオンにします。
- 迷ったら、非公開のままにしてください。公開は、あとからできます。

## 裏の名前
非公開のリポジトリ（private repository）と、公開のリポジトリ（public repository）です。履歴は、コミットの履歴（commit history）です。
