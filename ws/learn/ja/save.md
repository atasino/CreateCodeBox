# 学びカード: セーブ

## 一言で
セーブは、いまの作業の状態を、記録として残すことです。記録は、あなたのパソコンの中に残ります。

## たとえるなら
「名前を付けて保存」を、上書きせずに、何回分も残していくようなものです。1 回ごとに、日付と短いメモが付きます。

## いま起きること
- `bash ws/bin/ws.sh save "<note>"` を実行します。前回のセーブからの、プロジェクトの `src/` フォルダの中の変更が全部、あなたのメモ付きで記録されます。
- 記録する前に、ワークスペースが、決まった形式の鍵が混ざっていないかを確かめます（たとえば `sk-` や `ghp_` で始まる文字列）。見つかったら、止まって、何も記録しません。パスワードや、知らない形式の鍵は見つけられません。
- セーブは、あなたのパソコンの中だけで働きます。インターネットには何も送りません。
- 記録には、前の状態が残ります。前の状態に戻せる土台はあります。ただし、戻すための操作は、まだ用意していません。
- 自分の repo（作業の置き場。Git が管理しているプロジェクトのフォルダ）を持ち込んだ場合、セーブは `main`（本線）を使いません。`createcodebox/<date>` という名前のブランチ（本線とは別の作業の流れ）を使います。

## 気をつけること
- メモには、何を変えたかを 1 行で書いてください。あとで探しやすくなります。
- 鍵のせいでセーブが止まったら、その鍵を消して、もう一度セーブしてください。
- セーブはバックアップではありません。パソコンが壊れたら、記録も一緒になくなります。

## 裏の名前
Git のコミット（commit）です。1 つの記録が 1 つのコミットです。あなたのメモは、コミットメッセージと呼ばれます。
