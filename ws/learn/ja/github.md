# 学びカード: GitHub、ブランチ、repo の持ち込み

## 一言で
GitHub は、作ったもののコピーをネット上に置いておくサイトです。パソコンが壊れても、コピーは残ります。

## たとえるなら
銀行の貸金庫です。大事なノートのコピーを預けておきます。鍵を誰に渡すかは、あなたが決めます。ブランチ（作業用の枝）は、清書した原稿（`main`）のコピーに赤を入れて試すのに似ています。

## いま起きること
- repo（作業の置き場。Git が管理しているプロジェクトのフォルダ）が、GitHub 上であなたのプロジェクトを保管します。repo は GitHub のサイトで作ります。最初は**非公開（Private）**にします。手順は GitHub の案内にあります。
- `https://` で始まるウェブのアドレス（URL）を、`pm`（あなたが話しかけるアシスタント）に渡します。`pm` が `bash ws/bin/ws.sh repo link <URL>` を実行します。
- あなたが頼むと、`pm` が `backup` を実行します。セーブした記録を、その repo に送ります。最初に、セーブと同じ鍵の確認が働きます。repo が公開になっているときと、公開かどうか判断できないときは、バックアップは止まります。
- Git からサインインを求められたら、あなた自身が行います。Claude は、トークン（鍵の一種）やパスワードを必要としないように作ってあります。この手順は、まだ実際の GitHub では確かめられていません。
- **すでに repo を持っているなら、そう伝えてください。** `pm` が `bash ws/bin/ws.sh repo adopt <URL>` を実行します。`https://` で始まるウェブのアドレスか、SSH のアドレス（`git@` で始まるもの）が使えます。Claude は、最初にコードを読みます。その中の `CLAUDE.md` は読まないよう指示してあります。
- **ブランチ。** ブランチは、本線とは別に進める作業の流れです。本線は `main` と呼びます。repo を持ち込んだあと、セーブは `createcodebox/<date>` という名前のブランチを使います。作業が整ったら、あなたが自分で `main` に取り込みます（merge）。

## 気をつけること
- トークンやパスワードを、チャットに貼らないでください。Claude には要りません。
- repo を作るときは、**Private** を選んでください。
- 送ったものは、repo に残ります。鍵の確認は先に働きますが、知っているのは一部の鍵の形式だけです。
- 持ち込んだ repo では、セーブが自動でブランチを使うので、あなたが取り込むまで `main` はそのままです。
- SSH のアドレスでは、repo が公開かどうか判断できないので、バックアップは止まります。

## 裏の名前
リポジトリ（repository、略して repo）です。送ることはプッシュ（push）、repo のコピーはクローン（clone）です。プルリクエスト（pull request、PR）は、ブランチの取り込みをお願いするものです。マージ（merge）は、ブランチを `main` に入れることです。
